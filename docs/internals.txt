The architecture is a 16 bit one with 15 instructions. The main register is 16 bit wide

The visible register set is made by two registers: PC (the instruction pointer) and AC (the accumulator)


Full Register Set (Visible + Hidden)

PC - 16 bit  -- Visible, Program Counter
AC - 16 bit  -- ACcumulator register
DR - 16 bit  -- Data Register, contains the read data
TR - 16 bit  -- Temp Register, contains AC at the beginning of each instruction
AR - 16 bit  -- Address Register, output to the memory
IR - 04 bit  -- Instruction Register, contains the 4 bit opcode
CA - 16 bit  -- Constant Address 0x100, reset vector, hardwired inside Address Bus Control

Encoding

The encoding is composed of 4 bit opcode and 12 bit address/literal.

    0000 ADD @      0100 ----       1000 JMP @      1100 LDA @
    0001 SUB @      0101 LIT #      1001 JPI @      1101 LDI @
    0010 AND @      0110 INC @      1010 JNZ @      1110 STI @
    0011 NOR @      0111 SHR @      1011 JZE @      1111 STA @

Opcode 0100 is not implemented: it executes as a NOP.
The word 0x0000 is a valid ADD of the content of address 0.


Datapath

Shared buses

BUS_0 := MEM_D_IN (write) -> DR, IR                             one writer, the memory data input
BUS_A := PC, DR, CA (write) -> AR, and PC (read)                three writers, enabled by pc_wa / dr_wa / ldc
BUS_2 := UN, AC, FN, DR (write) -> TR, AC (read)                four writers, selected by bm[1:0]

ldc is an output enable and not a load: it drives CA onto BUS_A, and AR still
needs lar to latch it. A word that asserts ldc alone does nothing at all.

Direct links

AC          -> ALU port 0
DR          -> ALU port 1
DR          -> AluMem input (unary unit)
DR          -> PC input          PC can only ever be loaded from DR
TR          -> MEM data out      the value written by wm is always TR
AR          -> MEM address out   the memory is only ever addressed by AR
IR[1:0]     -> ALU function select
IR[0]       -> AluMem function select (0: DR+1, 1: DR>>1)
TR          -> zero detector     the branch condition is TR == 0, never AC

Control signals (the outputs of Microcode Control Unit

The microcode ROM is 128 x 24 and is addressed by uPC, a 7 bit counter with
parallel load. Every bit of the control word drives one signal directly, so no
gate stands between the ROM output and the datapath: all the logic of the unit
sits on the uPC path, which starts from flip flop outputs and has a full cycle
to settle.

The useq field of the control word picks the next uPC:

    next    uPC + 1
    dopc    { OPC, 100 }                  dispatch on the opcode from memory
    dir     { IR, 100 }                   dispatch on the opcode already in IR
    brz     { uPC[6:3], target } if TR == 0, uPC + 1 otherwise

dopc ends an instruction in the same word that fetches the next one, dir ends it
later. A routine that fetches early and keeps working with IR already loaded
therefore dispatches with dir. There is no gain in doing so while AR is the only
address source, because then the fetch can only be the last memory access of a
routine, but the choice belongs to the microcode and not to the wiring.

uPC counts across slot boundaries, so a routine may run out of word 7 of its slot
into the low words of the next one. Reset clears uPC.

Slot layout

Each opcode owns 8 words. Dispatch always enters at word 4, so words 0..3 of a
slot are unreachable from dispatch and are available as the tail of the routine
in the preceding slot. A routine may therefore be up to 8 words long, provided
the following slot holds a routine of at most 4 words.

Words 0..3 of slot 0 are reachable only out of reset, where uPC = 0, and hold the
boot sequence. Slot 15 has no successor, so the routine in slot 15 must fit in
words 4..7.

Control word (24 bit)

  23:18 reserved, zero
  17:16 useq      next, dopc, dir, brz
  15:13 target    target word of brz
  12:11 bm        BUS_2 writer
     10 tr_rd       9 ac_rd       8 pc_rd       7 inc
      6 ldc         5 lar         4 dr_wa       3 pc_wa
      2 wm          1 fetch       0 dr_rd

No field overlaps another.

Boot

    w0  ldc, lar                AR <- 0x100
    w1  dr_rd                   DR <- MEM[0x100]
    w2  dr_wa, lar, pc_rd       AR <- DR, PC <- DR
    w3  fetch, inc, dopc        IR, DR <- MEM[PC], PC <- PC + 1

The word at 0x100 is the address of the entry point, not an instruction.


Instruction timing

Legend
    @ : address                 # : literal
    <- : assign                 , : parallel, same clock cycle
    ; : await next clock        w<n> : word <n> of the slot

Every routine ends with the fetch of the next instruction, so there is no shared
fetch sequence and the dispatch cycle does useful work.

ADD @, SUB @, AND @, NOR @ : slots 0..3, 4 cycles

    w4  AR <- DR;
    w5  DR <- MEM[AR];
    w6  AC <- FN(AC, DR), TR <- FN(AC, DR), AR <- PC;
    w7  IR, DR <- MEM[AR], PC <- PC + 1

LIT # : slot 5, 2 cycles

    w4  AC <- DR, TR <- DR, AR <- PC;
    w5  IR, DR <- MEM[AR], PC <- PC + 1

INC @, SHR @ : slots 6, 7, 5 cycles

    w4  AR <- DR;
    w5  DR <- MEM[AR];
    w6  TR <- UN(DR);
    w7  MEM[AR] <- TR, AR <- PC;
    w0  TR <- AC, IR, DR <- MEM[AR], PC <- PC + 1      in the next slot

JMP @ : slot 8, 2 cycles

    w4  AR <- DR, PC <- DR;
    w5  IR, DR <- MEM[AR], PC <- PC + 1

JPI @ : slot 9, 4 cycles

    w4  AR <- DR;
    w5  DR <- MEM[AR];
    w6  AR <- DR, PC <- DR;
    w7  IR, DR <- MEM[AR], PC <- PC + 1

JNZ @ : slot 10, 3 cycles taken, 2 not taken

    w4  AR <- PC, brz w6;
    w5  AR <- DR, PC <- DR;
    w6  IR, DR <- MEM[AR], PC <- PC + 1

JZE @ : slot 11, 3 cycles taken, 2 not taken

    w4  AR <- PC, brz w6;
    w5  IR, DR <- MEM[AR], PC <- PC + 1
    w6  AR <- DR, PC <- DR;
    w7  IR, DR <- MEM[AR], PC <- PC + 1

LDA @ : slot 12, 4 cycles

    w4  AR <- DR;
    w5  DR <- MEM[AR];
    w6  AC <- DR, TR <- DR, AR <- PC;
    w7  IR, DR <- MEM[AR], PC <- PC + 1

LDI @ : slot 13, 5 cycles

    w4  AR <- DR;
    w5  DR <- MEM[AR];
    w6  AR <- DR;
    w7  DR <- MEM[AR], AR <- PC;
    w0  AC <- DR, TR <- DR, IR, DR <- MEM[AR], PC <- PC + 1      in the next slot

STI @ : slot 14, 5 cycles

    w4  AR <- DR;
    w5  DR <- MEM[AR];
    w6  AR <- DR;
    w7  MEM[AR] <- TR, AR <- PC;
    w0  IR, DR <- MEM[AR], PC <- PC + 1                          in the next slot

STA @ : slot 15, 3 cycles

    w4  AR <- DR;
    w5  MEM[AR] <- TR, AR <- PC;
    w6  IR, DR <- MEM[AR], PC <- PC + 1

STI is at opcode 1110 and STA at 1111 because STI needs five words and slot 15
has no successor to hold the tail.


Invariants the microcode relies on

TR holds AC at the start of every instruction. Only INC and SHR break it, and
they restore it in their tail. The branch condition and the value written by
every store both come from TR, so the invariant is what makes JNZ, JZE, STA and
STI correct.

A word that asserts wm never loads TR, so the value being written cannot change
during the write.

A word that asserts wm may load AR, but only because the write is a single pulse
that starts on the falling edge of the clock and ends before the next rising one:
write is wm gated with the inverted clock, and the memory latches on the rising
edge of write. In that window AR has been stable for half a cycle and has not yet
taken the value this word loads into it.

That pulse shape is the reason the microcode is allowed to write and reload AR in
one word, and it is not free to change. Gating wm with the clock high phase
instead does not work, whatever edge the memory latches on: wm falls after the
edge that ends the word, so a second write event lands exactly while AR is
changing, and every store writes twice, the second time to the address the next
word loads, which is the program itself.

The masking flag of DR follows flag' = FE | (flag & ~LD), so a full load clears
it: an ALU or LDA operand keeps all sixteen bits. If the flag could not be
cleared, every read datum would lose its top four bits.

A word that asserts brz is followed by the not taken path, and its target is the
first word of the taken path. Both paths end with a fetch of their own.

A word that asserts fetch never asserts dr_rd, and at most one of pc_wa and
dr_wa is asserted in the same word.
